# Редактируемый PSD: рабочий конвейер

## Основной маршрут: Photopea API

В исходной сессии Claude Code запускал Python-скрипты из shell. Playwright поднимал Chrome, рендерил собственный HTML, извлекал DOM-сцену и размещал Photopea в iframe. Команды импорта, обработки слоёв и экспорта выполнялись через официальный Live Messaging API. Этот же маршрут выбирай для Claude Code, когда его разрешает окружение.

Последовательность одной сборки:

1. HTML/CSS с локальными изображениями и шрифтами → отрисовка и извлечение сцены → SVG с текстом, фигурами, группами и clipPath.
2. Загрузка iframe Photopea → ожидание `done` → отправка SVG как `ArrayBuffer` через `postMessage` → ожидание `done`.
3. Отправка `.post.js` строкой: имена/видимость/opacity слоёв, настоящий многострочный текст, leading и tracking; затем `saveToOE('psd')`.
4. Получение бинарного PSD и `done` → запись на диск; при необходимости направляющие через PSD resource 1032.
5. Отдельный вызов `saveToOE('png')` → бинарное превью и `done` → сравнение с браузерным рендером, структурная и визуальная проверка.

Это браузерный API, а не отдельный REST-сервис обработки изображений. Playwright обслуживает браузер и обмен сообщениями; не требуется воспроизводить сборку кликами по меню Photopea. Для отдельных проверок исходная сессия также использовала интерфейс, клавиатуру и настоящие снимки редактора.

Локальный мост ниже — адаптация для сред с ограниченным управлением браузером; его кнопки запускают тот же `postMessage` и скрипты Photopea. Ручной импорт — запасной маршрут, а не стандартный способ массовой сборки.

## Состав

| Файл | Назначение |
|---|---|
| `scripts/scene.js` | Разложение отрисованного DOM на фон, фигуры, текст, изображения, SVG и группы |
| `scripts/scene_to_svg.py` | Чистое преобразование сцены в SVG, карту имён и post-script Photopea |
| `scripts/prepare_capture.py` | Добавление кнопки экспорта сцены в отдельную копию собственного HTML для разрешённого браузера |
| `scripts/build_pea.py` | Полный HTML → PSD/PNG конвейер в окружении с разрешённым самостоятельным Playwright |
| `scripts/build_batch.py` | Реестр листов, общая сессия редактора, выборочная пересборка, перезапуск и журнал ошибок |
| `scripts/pea_api.py` | Последовательные запросы через iframe; проверка источника сообщений и ожидание done |
| `scripts/psd_guides.py` | Направляющие в image resource 1032 без растрирования текстовых слоёв |
| `scripts/serve_bridge.py`, `assets/photopea-bridge.html` | Локальный интерфейс импорта SVG и записи PSD/PNG через разрешённый браузер |

Оригинальный проект использовал Pillow, psd-tools, Playwright и установленный Chrome. Определи доступный Python и пакеты, сначала проверь имеющийся runtime. Не устанавливай всё повторно. Если нужна зависимость, используй изолированную среду и кеш на D:. Не меняй глобальный Python и браузерную конфигурацию для этого навыка.

Самостоятельный Playwright используй только когда текущие инструкции это позволяют. Если UI должен управляться исключительно специальным browser/computer-use инструментом, запускай локальный сервер, взаимодействуй с его кнопками и Photopea разрешённым инструментом. Скрипт из пакета не является разрешением обойти инструментальные ограничения.

## Пробы перед масштабированием

При неизвестном окружении или новой возможности делай небольшие отдельные пробы: handshake/echo → документ и текст → настоящий шрифт → многострочный текст/leading/tracking → группы → SVG-фигура и фото/маска → PSD/PNG → повторное открытие и направляющие. Сохраняй результат и ошибки в `_work/qa/`. В событиях 1361–1475 исходной сессии именно такие пробы определили рабочий маршрут. Не запускай длинный скрипт с несколькими непроверенными функциями: отсутствие `done` затруднит поиск причины. Возможности Photoshop Scripting DOM и Action Manager проверяй по нужной операции; сходство API не означает полной поддержки.

## Схема сцены

Верхний уровень: `width`, `height`, `bg`, `items`. Элементы имеют `type`, `name`, `groups`, `x/y/w/h` там, где применимо, `opacity`, `hidden`.

- `rect`: `rx`, `fill:{c,a}`, необязательные `stroke:{c,a,w}`, `grad:{ang,stops:[{c:{r,g,b,a},o}]}`.
- `text`: `lines`, baseline `x/y`, `font` (PostScript), `size`, `lead`, `tracking`, `align`, `color`.
- `image`: локальный `src`, геометрия полного изображения и `clip:{x,y,w,h,rx}`, необязательный `sepia`.
- `path`: `d`, `stroke:{c,w}`.
- `svg`: `svg:{inner,vb:[x,y,width,height]}`, геометрия.
- `raster`: data URI и геометрия только для осознанно растровой графики, например сложной иллюстрации.

SVG содержит `<g>` для групп, `<text>` для текста, фигуры для подложек, `<image>` с встроенными локальными фотографиями и `<clipPath>` для кадрирования. Post-script переименовывает слои, восстанавливает многострочный текст через `\r`, интерлиньяж, tracking и прозрачность. В SVG сначала записывается первая строка, затем текст обновляется в Photopea — это часть конвейера, которую нельзя пропустить.

Для снимка DOM дождись `document.fonts.ready` и декодирования всех изображений. `scene.js` — доверенный код пакета для извлечения собственного HTML; доступ к DOM осуществляй разрешённым в окружении способом. Он возвращает объект сцены, а ссылки на inline SVG держит в `window.__S`, на неподдерживаемые фрагменты — в `window.__R`. Для inline SVG клонируй элементы и встрои computed fill/stroke/font вместо внешних CSS-классов. Полный runner уже делает это. Неподдерживаемые фрагменты требуется обработать или упростить; экспортировать пустой элемент нельзя.

## Команды

Из каталога навыка; пути проекта передавай как отдельные аргументы:

```powershell
python scripts/build_pea.py "project/_work/pages/out/01_home.html" "project/_work/out/mock/01_home.psd" --width 1440 --grid --container 1170 --columns 12 --gutter 30 --fonts "project/_work/fonts.json"
python scripts/build_batch.py "project/_work/build-jobs.json" --only home-mock home-proto
python scripts/scene_to_svg.py "project/_work/01_home.scene.json" "project/_work/01_home.svg"
python scripts/prepare_capture.py "project/_work/pages/out/01_home.html" "project/_work/pages/out/01_home.capture.html" --width 1440 --fonts "project/_work/fonts.json"
python scripts/serve_bridge.py --root "project/_work" --output "project/_work/out/mock" --port 8765
python scripts/psd_guides.py "project/_work/out/mock/01_home.psd" "project/_work/out/mock/01_home-guides.psd" --width 1440 --container 1170 --columns 12 --gutter 30
python scripts/verify_psd.py "project/Сдача/PSD" --manifest "project/_work/psd-manifest.json" --json "project/_work/qa/psd.json"
python scripts/compare_renders.py "project/_work/out/mock/01_home_browser.png" "project/_work/out/mock/01_home.png" "project/_work/qa/home"
```

Runner сохраняет PNG из браузера и Photopea. `--pre` задаёт путь доверенного JS-преобразования собственной страницы; `--arg` — JSON-файл с его аргументами. Это позволяет строить нейтральный прототип из той же геометрии. Напиши такой преобразователь под CSS текущего проекта, включая заглушки и аннотации; музейный набор селекторов не универсален.

### Пакетная сборка

Пути в `build-jobs.json` задаются относительно его папки. `pre_arg` — JSON-значение, `pre_js` — файл JS-функции. Для скетчей один HTML может запускать функцию отрисовки с разными ключами страниц. Пример:

```json
{"jobs": [
  {"id": "home-mock", "html": "pages/out/01_home.html", "psd": "out/mock/01_home.psd", "width": 1440, "fonts": "fonts.json", "grid": {"container": 1170, "columns": 12, "gutter": 30}},
  {"id": "home-proto", "html": "pages/out/01_home.html", "psd": "out/proto/01_home.psd", "width": 1440, "pre_js": "wire.js", "pre_arg": [{"sel": ".hero", "text": "Основное действие"}]},
  {"id": "home-sketch", "html": "sketch/sheet.html", "psd": "out/sketch/home.psd", "width": 2400, "pre_js": "draw-sheet.js", "pre_arg": "home", "fonts": "fonts.json"}
]}
```

Runner переиспользует редактор, закрывает документ после каждого листа и перезапускает браузер после серии (по умолчанию 8 листов, параметр `--restart-every`). После ошибки следующий лист получает новый экземпляр. Журнал `.build-results.json` различает `built` и `failed`; ненулевой exit code сообщает неполный комплект. `built` означает получение файлов, не успешное визуальное QA. Выбор `--only` удобен для исправлений; после изменения общего CSS пересобери все зависимые листы. Параллельные процессы допустимы при независимых заданиях, экземплярах и выходных путях.

Конвертер без браузера создаёт `.svg`, `.post.js`, `.layers.json`. Локальный мост открывается по `http://127.0.0.1:8765/__photopea_bridge`. Укажи относительный путь SVG и нажми импорт: байты передаются iframe Photopea, post-script сохраняет PSD, сервер пишет результат в выбранную папку. Затем сохраняй PNG и проверяй слои/вид. Мост не требует доступа к DOM редактора через сторонний скрипт автоматизации. Можно импортировать и проверять SVG вручную через сам редактор и File → Script.

Для извлечения сцены без самостоятельного Playwright создай `01_home.capture.html` рядом с исходным HTML. Задай ожидаемую ширину `--width` и такую же ширину viewport разрешённым browser-инструментом, чтобы CSS-breakpoints и геометрия соответствовали холсту. Открой страницу через локальный сервер и нажми «Экспортировать сцену для PSD». JSON сохраняется в выбранный `--output`; локальные HTTP-пути изображений заменяются на соответствующие пути проекта. Затем используй конвертер и мост. Кнопка исключается из сцены. Подготовь HTTP-relative изображения/шрифты; оригиналы загрузок остаются на D:, рабочие копии можно разместить в проекте. При неподдерживаемом raster fallback экспорт сообщает ошибку — упрости CSS или обработай фрагмент явно.

## Шрифты

`fonts.json` — карта семейств и реальных начертаний:

```json
{
  "Manrope": {"400": "Manrope-Regular", "700": "Manrope-Bold"},
  "Cormorant Garamond": {"500": "CormorantGaramond-Medium", "700": "CormorantGaramond-Bold", "500italic": "CormorantGaramond-MediumItalic"}
}
```

Карта задаётся из проверки редактора или метаданных файла шрифта, а не из догадки. Загрузку дополнительных ресурсов Photopea можно делать через конфигурацию `resources` или бинарный импорт; соблюдай правила передачи данных текущего окружения. Загруженные файлы и лицензии сохраняй на D:. В комплекте не предполагается наличие шрифтов из старого проекта.

Встроенная карта scene.js поддерживает шрифты исторического образца, но новый проект всё равно проверяет нужные начертания. Неизвестные семейства и отсутствующие начертания явной карты дают ошибку; скрытая подмена Arial не считается успехом.

В старой среде Caveat не отрисовал кириллицу как ожидалось; Neucha работал. Это наблюдение, не вечный запрет Caveat. Проверяй текущую редакторную версию и свои файлы шрифтов. Браузер умеет синтезировать жирный для Prata, импортируемый файл — не обязательно. Используй реальное начертание или выбери другой шрифт.

Не объединяй русский заголовок и китайский декоративный знак в один текстовый слой с неподходящим шрифтом. Разделяй по отдельным блокам/слоям. Текст внутри одного блока с разными цветами, весами или шрифтами тоже разбивай явно: старый сборщик выбирал доминирующий стиль по самому длинному узлу.

## Неочевидные дефекты

- `postMessage` отправляет скрипт строкой, файл как ArrayBuffer; после инициализации и операции Photopea сообщает `done`. Запросы последовательны. Проверяй источник iframe и origin; не принимай случайные сообщения страницы.
- Не угадывай длительность загрузки фиксированным sleep. Используй подтверждение `done` и ограниченный timeout. При ошибке не помечай файл собранным; допускается один повтор с новым редакторным экземпляром после диагностики. Повторные одинаковые ошибки требуют смены подхода или сообщения ограничения.
- SVG-opacity на изображении в старой версии не сохранялся как ожидалось. Post-script задаёт opacity слоя и сбрасывает двойное применение в группе маски. Проверь карточку disabled/«мест нет» в рендере.
- `50%` border-radius и вертикальные надписи требуют отдельного просмотра. В сравнении не масштабируй один рендер под другой: это скроет неправильную геометрию.
- CSS transform, сложный background, тени, смешанные стили и inline SVG могут перейти в fallback. Основной текст и кнопки должны остаться редактируемыми. Упростить оформление предпочтительнее, чем растрировать всю секцию.
- Слой или группа Clip-Path при импорте не доказывают наличие маски: проверь PSD и кадрирование в редакторе.
- Для направляющих записывается PSD resource 1032: позиции в единицах 1/32 px, 0 — вертикаль, 1 — горизонталь. Пиши исходный PSD record, не пересобирай композицию из пикселей.
- Сохранение обычных фотографий пиксельными слоями допустимо, если задача это разрешает; наличие таких слоёв не означает, что весь файл плохой. Недопустимо выдавать растровый текст за редактируемый.
