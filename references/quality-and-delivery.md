# Реестры, проверки и комплект

## Требования

Создай JSON после изучения текущего описания сайта и референсов. Это пример структуры, а не заполненный список требований:

```json
{
  "topic": "Тема сайта",
  "viewports": [1440, 390],
  "editor": "Photopea",
  "requirements": [
    {"id": "purchase-flow", "source": "Описание пользователя", "text": "Полный сценарий покупки", "evidence": "Макеты выбора, данных, оплаты и результата", "status": "pending"}
  ]
}
```

В требовании должны быть ссылка на исходное условие и наблюдаемая проверка. `pending` изменяется после проверки результата. Пример проекта не заменяет это чтение.

## Реестр артефактов

```json
{
  "pages": [{"id": "home", "title": "Главная", "task": "Выбор основного раздела", "sketch_sheet": "sketch/01_home.psd", "selected_option": "Б"}],
  "states": [{"id": "purchase-success", "page_id": "tickets", "trigger": "Подтверждение покупки", "result": "Данные билета"}],
  "artifacts": [{"page_id": "tickets", "state_id": "purchase-success", "html": "pages/out/08d_success.html", "prototype": "out/proto/08d_success.psd", "mockup": "out/mock/08d_success.psd", "editor_shot": "out/pp/ticket-success.png", "preview": "out/previews/08d_success.png"}]
}
```

Все пути относительно проекта. Добавляй записи для каждой страницы/состояния; одинаковые названия упрощают сопоставление скетч → прототип → макет → PSD/превью. Не выводи количество страниц из количества состояний.

## PSD manifest

`verify_psd.py` проверяет каждый фактический PSD и сравнивает список с manifest. Пример:

```json
{
  "files": [
    {"path": "4. Макеты/01 Макет - Главная.psd", "width": 1440, "min_text": 1, "min_shapes": 1, "require_guides": true, "require_masks": true},
    {"path": "1. Скетчи/01 Скетчи - Главная.psd", "min_text": 1}
  ]
}
```

Требование масок относится к файлам с кадрированными фото/соответствующим условием. Не требуй маску там, где её не должно быть. Одна надпись в статистике не доказывает редактируемость всех подписей: дополнительно проверь нужные `required_text_layers`, содержание и реальные выборки в редакторе. Инвентаризация показывает kind, группы, используемые шрифты, маски, размеры, направляющие. Ошибки дают ненулевой exit code.

## Визуальная проверка

Проверь каждый лист в достаточном масштабе и обзор всей системы:

- Шапка: меню не переносится случайно, активный раздел и языки согласованы, действие доступно.
- Первый экран: иерархия, читаемость поверх изображения, кадрирование, кнопки, внешние поля.
- Основная часть: сетка, ритм, длина заголовков, таблицы/цены/фильтры/карточки, отсутствие обрезанных блоков.
- Формы: метки, выбранное/неактивное, ошибки, доступный focus, ясный результат действия.
- Подвал: нет переполнений, текста на фоне низкого контраста, случайных переносов адреса или контактов.
- Длинные страницы: просмотр участками с перекрытием, а не только уменьшенный общий снимок.
- Photopea: выбранные шрифты, переносы, круги, прозрачность, маски, знаки языка; совпадение с исходником.

После исправления общего CSS пересмотри все использующие его типы страниц. Устаревшие скриншоты должны быть заменены. Наличие файлов и успешный CLI не заменяют просмотр.

## Комплект дизайна

Стандартная выдача: финальные макеты всех согласованных страниц, состояний и размеров; PNG/JPEG-превью; редактируемые PSD. Имена файлов должны однозначно отражать экран, состояние и ширину. Организуй понятные группы слоёв и сохраняй выбранную систему шрифтов, цветов, компонентов и направляющих.

Проверь соответствие каждого превью окончательному PSD. Для длинных страниц добавь обзор и читаемые участки; пользователь должен видеть дизайн без открытия редактора. При полезности или по запросу включи локальное HTML-превью и только необходимые ресурсы.

Исследования, сравнения, скетчи, прототипы, реальные снимки Photopea и журнал решений сохраняй в рабочей папке для продолжения. Включай промежуточные материалы в выдачу по запросу или для использования дизайна. Курсовая, методичка, DOCX/PDF-отчёт, титул и оглавление не являются стандартными deliverables.

Краткая сопроводительная заметка допустима: состав экранов, выбранные шрифты, источники изображений, демонстрационные данные и конкретные ограничения. Она не должна превращаться в отдельный учебный документ. Для аудитории различай факт и гипотезу; демонстрационные контакты/цены/имена не выдавай за данные исследования.

## Передача

Сверь состав с реестром. Не считай дополнительные состояния отдельными страницами и не используй старые цифры после правок. HTML, SVG, скрипты и данные источников сохраняй для редактирования и восстановления; в итоговый комплект включай запрошенные и необходимые для использования дизайна файлы.

Если собираешь ZIP, проверь целостность, список вложений и совпадение контрольных сумм с финальными файлами. После изменения макетов пересобери превью и архив. В ответе покажи дизайн и дай ссылки на превью, редактируемые исходники и архив.

Готовность означает: согласованные экраны и состояния созданы, артефакты согласованы, файлы редактируемы, рендеры просмотрены, превью и архив актуальны. Непроверенный пункт отмечается явно.
